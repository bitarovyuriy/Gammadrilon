# Главный экран Gammadrilon (v3.5) — план

## Задача

Дать приложению стартовый экран, на котором человек сам собирает себе пульт:
выбирает виджеты нужных подсистем, двигает их, меняет ширину и высоту. Раскладка
запоминается и переживает перезапуск. Виджеты не дублируют логику подсистем —
они читают те же данные и дёргают те же действия, что и полные вкладки.

Всё остальное в приложении остаётся как есть: вкладки, трей, правила, обновление.

## Референсы и что из них берём

| Источник | Что взято |
|---|---|
| Windows Widgets Board | плитки разного размера в сетке, перетаскивание за заголовок, изменение размера, «закрепить/убрать» |
| Home Assistant, раздел Dashboard chapter 1 (drag-and-drop, Sections view, grid system) | сетка с явными колонками, перетаскивание с подсветкой места вставки, ширина плитки кратна колонке, режим правки отдельным переключателем |
| Обзоры bento-сеток (orbix.studio, sabaoon.dev) | одна плитка — одна мысль; размер плитки = вес информации; крупное число + единица + статус-точка, без декора |
| PyQt drag&drop (pythonguis) | перетаскивание своим `mouseMoveEvent` + `QDrag`, без `QDockWidget` |

Из этого — решение ниже: **строки по 12 колонок**, у строки своя высота, у плитки
своя ширина. Пересечений и коллизий в такой модели не бывает, поэтому
перетаскивание и изменение ширины можно сделать честно и без эвристик.

## Модель раскладки

- Ширина страницы делится на **12 колонок**, шаг 1.
- Страница — список **строк**. У строки высота `S` / `M` / `L` (104 / 140 / 208 px).
- Строка — список плиток. Сумма ширин в строке всегда ровно 12.
- Плитка: `id` из каталога + `w` (3…12, кратно 1).
- Файл: `gd_paths.data_dir()/dashboard.json`, запись атомарная через
  `gd_state.write_json_atomic` (как остальные state-файлы приложения).

```json
{
  "version": 1,
  "rows": [
    {"h": "M", "tiles": [{"id": "w.cpu", "w": 4}, {"id": "w.gpu", "w": 4}, {"id": "w.ram", "w": 4}]},
    {"h": "S", "tiles": [{"id": "w.power", "w": 6}, {"id": "w.dns", "w": 6}]},
    {"h": "M", "tiles": [{"id": "w.zapret", "w": 12}]}
  ]
}
```

`normalize()` чинит любой мусор: неизвестные id выбрасываются, дубли — тоже,
`w` зажимается в `[min_w, max_w]`, сумма доводится до 12 (остаток отдаётся
плиткам по порядку, лишнее переносится в новую строку), пустые строки
удаляются, пустая раскладка заменяется раскладкой по умолчанию. Файл читается
терпимо: битый JSON — раскладка по умолчанию, битый файл уезжает в `.bak`.

## Каталог виджетов v1

| id | Что показывает | Действие | Источник данных |
|---|---|---|---|
| `w.cpu` | загрузка %, частота, мини-график за 60 с | открыть «Питание CPU» | `gd_metrics.cpu()` |
| `w.gpu` | загрузка %, температура, потребление, лимит | открыть «Питание GPU» | `gd_metrics.gpu()` (`util`, `temp`, `pl`) |
| `w.ram` | занято % и ГБ | кнопка «Очистить» → вкладка «Утилиты» | `gd_metrics.ram()`, `psutil` |
| `w.power` | профиль CPU сегментами ЭКО / НОРМА / БУСТ | `page.apply_profile(pid)` | `gd_power.state_snapshot()`, `gd_power.PROFILES` |
| `w.gpu_limit` | лимит Вт + профиль GPU чипами | `page.apply_profile(name)` | `gd_metrics.gpu()`, `gd_gpu.GPU_PROFILES` |
| `w.gamma` | пресеты гаммы чипами, текущая яркость | `host.apply_preset_by_index(i)` | `host.config["presets"]` |
| `w.dns` | резолвер, режим, возраст замера | «Замерить» → `gd_metrics.request_dns()` | `gd_metrics.dns()`, `gd_dns.current_state()` |
| `w.zapret` | стратегия, GameFilter, IPSet, кто держит обход | тумблер вкл/выкл, список стратегий, чипы IPSet / TCP / UDP | `gd_zapret.snapshot()` |
| `w.rules` | число правил, последнее срабатывание | открыть «Правила» | `gd_rules.load_rules()`, `gd_rules.recent_fires()` |
| `w.journal` | три последние записи журнала | открыть журнал | `gd_journal.recent(3)` |

Правила для плиток:

- Плитка не строит ленивую страницу в конструкторе. Полный экран поднимается
  только по действию (клик, кнопка) — через `host._ensure_page(key)`.
- Плитка не запускает свои подпроцессы: `nvidia-smi`, `netsh`, `sc query` берутся
  из общего кэша `gd_metrics` или читаются не чаще одного раза в 5 с.
- Ошибка источника — честная строка в плитке («нет данных», «нет прав»), не
  пустое место и не ноль.

## Режимы

**Обычный.** Клик по плитке открывает её раздел (или выполняет действие, если у
плитки одно главное действие). Наведение — подсветка рамки, курсор-рука.
Живые значения обновляются таймером 1 с из одного снимка метрик.

**«Правка».** Кнопка в шапке главного экрана, рядом — «+ Виджет» и «Сброс».

- Плитки получают пунктирную рамку и ручку захвата; действия внутри не срабатывают.
- Перетаскивание за любое место плитки: подсветка места вставки вертикальной
  линией; отпускание — плитка встаёт в новую позицию (`move_tile`).
- Ручка на правом краю плитки тянет ширину: соседняя плитка в строке отдаёт или
  забирает колонки (`set_width`), ниже `min_w` не опускается.
- Контекстное меню плитки: «Открыть раздел», «Убрать».
- «+ Виджет» — диалог каталога: список с чекбоксами, уже стоящие отключены.
- «Сброс» — подтверждение и раскладка по умолчанию.
- Каждое изменение сразу пишется в файл (атомарно), без кнопки «Сохранить».

## Интеграция в `main.py`

1. `_add_page(None, "tab.home", factory=self._make_home_page)` — **первым**, до
   страницы гаммы (порядок вызова задаёт индекс в `QStackedWidget`).
2. `_make_home_page()`: импорт `gd_dashboard_ui`, `DashboardWidget(host=self)`,
   сохранить в `self._home_page`. Ленивая фабрика — как у остальных страниц.
3. `_rebuild_sidebar`: в кортеж `layout` первым элементом `("page", "tab.home")`.
4. `SIDE_ICONS["tab.home"] = "home"`.
5. Стартовая вкладка: если в конфиге нет `last_page_key`, открывать `tab.home`
   (сейчас при пустом ключе остаётся гамма).
6. Палитра команд (`gd_palette`): добавить пункт «Главный экран».

## Данные и обновление

`DashboardWidget` держит один `QTimer(1000)`. На тик: `snap = gd_metrics.snapshot()`,
затем `tile.update_metrics(snap)` по списку. Медленные источники (zapret, power,
rules, journal) обновляются реже — раз в 5 с, отдельным счётчиком тиков, и только
для плиток, которые реально стоят на экране.

Когда страница не видима (`isVisible()` ложно) — таймер работает, но медленные
источники пропускаются.

## Проверки

1. `python -m pytest tests -q` — весь набор, включая новые тесты модели.
2. `python -m ruff check .` — без новых замечаний.
3. `QT_QPA_PLATFORM=offscreen` — рендер главного экрана в PNG обеих тем,
   глазами проверить: плитки не наезжают, текст не обрезан, монохром без цвета.
4. Живой запуск `python main.py`: главный экран открывается, раскладка меняется,
   после перезапуска — та же.
5. `tests/test_meta.py` — проверка парности RU/EN сама поймает забытые ключи.

## Чего в v3.5 нет

- Свободного перетаскивания по двумерной сетке с разрешением коллизий — строки
  дают то же самое без эвристик.
- Нескольких сохранённых раскладок и профилей «игра / работа».
- Виджета на рабочий стол и в трей.
- Своих настроек у плитки (например, выбор конкретного диска в `w.ram`).

## Открытые вопросы

- Нужен ли `w.hotkeys` (стоп-кран, тихий час, снимок настроек) — упирается в то,
  какие действия `HotkeyManager` готов отдать наружу.
- Порог «сколько плиток в строке» на узком окне (минимум окна 910 px): при ширине
  меньше 1000 px, возможно, переходить на 6 колонок. Решение — после первого
  живого прогона.

## Правки после первого живого прогона (27.10.2026)

**Старт всегда на «Главном».** Окно больше не возвращается на последнюю вкладку:
`last_page` убран из `DEFAULT_CONFIG`, `__init__` не читает его, `_on_tab_changed`
не пишет. Главный экран — пульт, ради него приложение и открывают; прежняя
вкладка остаётся в памяти только на время сеанса.

**Плитка «Обход DPI» стала управляющей.** Раньше показывала «работает» и всё.
Теперь внутри: тумблер вкл/выкл, выпадающий список стратегий (`general*.bat` из
папки zapret), чипы IPSet / TCP / UDP для GameFilter. Своей логики у плитки нет —
она зовёт публичные `quick_*` методы экрана zapret:

| действие плитки | метод экрана | что происходит |
| --- | --- | --- |
| тумблер, обход наш | `quick_stop()` / `quick_start()` | гасит или поднимает winws приложения |
| тумблер, обход от службы | `quick_service("stop")` | останавливает саму службу zapret |
| выбор стратегии | `quick_strategy(id)` | запоминает выбор, работающий обход переосваивает и перезапускает |
| чипы TCP / UDP | `quick_game_filter(tcp, udp)` | включает GameFilter в нужном режиме |
| чип IPSet | `quick_ipset(on)` | трогает списки `lists\ipset-all.txt` |

Почему тумблер различает «наш winws» и «службу»: обход, поднятый службой
zapret, приложению не принадлежит, и старый `_off()` честно отвечал «нечего
останавливать». Теперь в такой ситуации гасится служба.

Плитка читает `gd_zapret.snapshot()` в фоне (`refresh_slow`, раз в 5 тиков) —
на GUI-потоке снимок занимает ~0,6 с и подвесил бы весь экран. Перед действием
`quick_ready()` дожимает первый снимок синхронно: иначе список стратегий пуст, а
решение «перезапускать ли» принимается по пустому словарю.

Высота строки: `_row_height()` берёт S/M/L из модели, но не ниже
`CATALOG[id]["min_h"]`. У `w.zapret` это `L` — четыре ряда контролов в строку
104 px не влезают. В раскладке по умолчанию плитка стоит отдельной широкой
строкой (`w: 12`), иначе список стратегий обрезается.
