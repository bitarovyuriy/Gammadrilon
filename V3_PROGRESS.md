## Решения / допущения

- Стек: Python 3.14 + PyQt5 (существующий проект). ДОПУЩЕНИЕ.
- «Компаньон» вместо службы: всё работает без админа; отдельный процесс нужен
  только для отката после краха UI. ДОПУЩЕНИЕ (промпт допускает «служба ИЛИ хелпер»).
- PERFEPP: слайдер 0–100 (0 = производительность, 100 = энергосбережение).
- Откат: авто при выходе/краше + кнопка «Вернуть как было».
- **Фоновые действия не поднимают UAC.** Всё, что идёт не из клика пользователя
  (сработавшее правило), выполняется только через уже живой elevated-хелпер: окно
  запроса прав поверх чужой игры — недопустимый сюрприз. Нет сессии → честный отказ
  в логе правил и статусбаре. Явные действия (вкладки, палитра, трей) поднимают хелпер
  как раньше — это осознанный клик.
- **Порядок обхода Tab — часть UX, а не деталь:** меню → содержимое страницы → шапка →
  кнопки окна (`_fix_tab_order`). Любой новый контейнер в титлбаре должен попадать в
  `tail` (по `objectName`) или считаться частью страницы.
- **Компаньон — только на записи.** Пассивное чтение состояния не поднимает процесс
  никогда (см. `gd_power_ui.read_status`): иначе вкладка CPU, открытая на старте, рождает
  компаньона до первого действия пользователя, а честный фут при этом пишет «служба не
  запущена». Первый шаг страницы, который «просто опрашивает», — место, где это ломается.

## Грабли (для будущих этапов)

- Из терминала Hermes: `env -u PYTHONPATH` при работе с проектным venv — Hermes
  протаскивает свой PYTHONPATH, pip видит чужие пакеты («already satisfied»).
- QT_PLUGIN_PATH-фикс обязателен в каждом исполняемом скрипте с PyQt5 (кириллица
  в пути), и ставить его до первого импорта PyQt5.
- **Цепочка фокуса (`nextInFocusChain` / `setTabOrder`) — три ловушки:**
  (1) держите обёртки PyQt живыми, пока обходите цепочку (`keep.append(w)`) — иначе
  `id()` переиспользуется и обход обрывается на середине (в приборе §7 это давало
  14 «остановок» вместо 29); (2) в `__init__` окно ещё не показано, поэтому у всех детей
  `isVisible() == False` — фильтруйте через `isVisibleTo(self)`; (3) пара
  `QWidget.setTabOrder(окно, виджет)` цепочку не переставляет — работает
  последовательность `setTabOrder(anchor, target)` с движущимся якорем (см.
  `main.py:_fix_tab_order`).
- Именованный канал, созданный elevated-процессом, обычному (не-elevated) клиенту
  недоступен (WinError 5, ACL). Связь UI ↔ elevated-хелпер — loopback TCP 127.0.0.1
  со встроенным handshake `authkey` из multiprocessing.connection.
- Сборочный venv (`C:\gd_build\.venv`) живёт отдельно от dev-venv: пакет, которого в нём
  нет (тот же `psutil`), молча выпадает из exe — PyInstaller пишет только WARNING про
  hiddenimport. Перед сборкой: `pip install -r requirements.txt` в сборочный venv и
  живая проверка того, что от этого пакета зависит (статусбар/правила/журнал).
- **PowerShell в периодическом опросе — ловушка по CPU.** `Get-NetIPConfiguration` стоит
  ~3 с CPU за запуск (CIM + автозагрузка модуля), поэтому раз в 30 с это ~8 % ядра, и
  заметить это можно только по дереву процессов: у самого приложения счётчик чистый.
  Правило: в фоновых тиках — нативный Win32 (iphlpapi/pdh/ctypes) или `netsh`, а
  PowerShell — только на явное действие пользователя. Второе правило: если значение нужно
  не постоянно (DNS-конфигурация), фон не опрашивает его вовсе — читаем по запросу и
  показываем возраст данных. Мерить — `_tmp_idle.py` (CPU по дереву) и
  `_tmp_dns_watch.py` (какие внешние утилиты вообще запускаются в окне наблюдения).
- **Лишний `pythonw.exe main.py` в дереве dev-запуска — это НЕ перезапуск приложения.**
  Проверка `_tmp_tree.py` (pid/ppid/cmdline/образ каждого ребёнка) показала: спустя ~10 мс
  после старта venv-овый `pythonw.exe` (237 КБ, редиректор) порождает **базовый
  интерпретатор** — у ребёнка `cmdline` совпадает с корнем, а `exe()` указывает на
  `…hermes\tools\python-3.14.7…\pythonw.exe`. Урок: судить о ребёнке надо по `exe()`
  (образ), а не по `name()`/`cmdline` — иначе легко принять редиректор venv за второй
  экземпляр или за компаньона. Для собранного exe аналог — bootstrap-родитель onefile.
  Проверять дерево — `_tmp_tree.py`.
- **Откат профиля питания — обязанность того, кто жив дольше.** Компаньон откатывает при
  смерти UI, но перезагрузка или убийство самого компаньона оставляют клон схемы
  активным, а state-файл — живым. Поэтому остаток профиля откатывается ещё и при запуске
  (`gd_power_ui.PowerWindow._rollback_leftover`, один раз за сессию): иначе UI показывает
  применённый профиль, которого никто не сторожит, а фут честно говорит «служба не запущена».
- Дерево процессов **собранного** exe мерить `_tmp_exe.py` (запускает exe, печатает образ
  и cmdline каждого ребёнка, гасит всё после себя), в dev — `_tmp_tree.py`.
